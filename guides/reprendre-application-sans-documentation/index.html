Comment reprendre une application sans documentation ?

Comment reprendre une application métier sans documentation : accès, code, architecture, base de données, dépendances, risques et stabilisation.

Publié et mis à jour le 16 octobre 2026 · Auteur : STRIVOR

Priorités

Reconstruire la connaissance avant de modifier le système.

1. Sécuriser les accès

Dépôts, serveurs, bases, DNS, certificats, CI/CD, sauvegardes et comptes techniques.

2. Cartographier l'architecture

Applications, APIs, bases, batchs, services externes, échanges et dépendances.

3. Reproduire le build

Être capable de reconstruire l'application dans un environnement contrôlé.

4. Comprendre les données

Schémas, migrations, volumétrie, sauvegarde et restauration.

5. Identifier les risques

Versions obsolètes, secrets, composants vulnérables et points uniques de défaillance.

6. Documenter en avançant

Chaque investigation doit enrichir la documentation pour ne pas recréer la dépendance à une seule personne.
